# QC v1：核验完整性与报告交付

本轮不新增模型角色或模型调用。优先复用已有分析、图表证据与事实核验结果，通过确定性规则控制正式报告内容。

## 执行流程

1. 正文输出先将字符串形式的 `evidence` 规范为单元素数组，避免原主张因字段类型不符被静默跳过；其他无效结构仍明确报告。
2. 正文与图表使用同一个 `collect_claims` 清单。事实核验仍保持原有最多 20 条的调用范围；QC 检查完整有效清单，超出的主张按未核验处理，不增加模型调用。
3. 检查主张 ID、漏项、重复、未知核验项、核验文本是否对应原主张，以及引用 ID 是否属于当前证据索引。
4. 仅当唯一对应的核验判定为 `supported`、引用有效且至少一段证据能在所引位置精确定位时，主张才可交付。兼容完整引号内的原文，不做语义相似度推测。定位检查不等于独立验证语义蕴含。
5. 正式摘要和总结由可交付主张原句组成。其他生成字段只有与可交付主张精确对应才保留，否则显示待核验。原始输出保存在 `structured_data.qc_draft`，Markdown 附录显示部分草稿。
6. 主模板入口执行 QC，因此新运行的 CLI、API 报告和 JSON 交付字段一致；不会出现只检查内部展示函数、最终模板却绕过闸门的情况。

`partially_supported` 不会自动改写成较弱结论。缺少语义复查时保留待核验，比机械删词后放行更可靠。

## API 与状态兼容

- `AnalysisResult`、任务详情、报告接口、产物接口新增可空的 `quality` 字段。
- `quality.status` 为 `passed`、`needs_review` 或 `blocked`；未执行 QC 的旧产物及通用文本模式保持 `null`，不能解释为通过。
- 执行状态 `completed` 表示流程和产物保存完成，与质量状态独立。`blocked` 仍允许查看带标记的草稿，不生成肯定式正式总结。
- `quality` 记录有效清单大小、无效主张数量、对应核验数量、覆盖率、可交付 ID、问题位置和报告字段绑定。覆盖率仅针对有效清单；无效结构单独显示，不能用覆盖率掩盖它们。
- `passed` 仅表示本轮规则检查未检出问题，不是医学质量认证或正确率保证。
- 原有 JSON 的 `summary`、`key_points`、研究提取和图表分析字段现在受交付闸门约束；需要分析原始生成内容的调用方应读取 `qc_draft`。证据提取记录与模型核验意见仍保留，报告明确标注它们的性质。

## 证据版本

结构修复前保留 parser 的原始章节快照，避免把模型改写的章节作为“原文”通过精确定位检查。已有章节 ID 保持含义，结构修复新增但未绑定 parser 的内容不会被自动认可。

首次 QC 保存证据索引内容的指纹和有效 ID 清单。已有 QC 结果在不同证据内容上重渲染时，输出 `source_changed` 并阻止复用旧支持判定。旧报告首次离线检查没有历史指纹，只能针对本次提供的原文做定位，不能追溯证明原模型当时读取了哪个文档版本。

## 离线复核

```bash
bash scripts/run.sh python scripts/check_report_quality.py \
  --source ref_baseline/s41467-025-64293-2.pdf \
  --report output/audit-complete.json \
  --output output/audit-qc
```

生成新的 Markdown、JSON 和解析产物，不覆盖输入报告，不调用 LLM。脚本成功退出表示离线检查执行完成；交付是否通过应读取 `quality.status`。

当前真实结果回放：旧报告的有效核验清单为 16 条，另有 15 条原始主张因 `evidence` 为字符串而结构无效；旧流程已经回退为摘要 / 要点核验，不能把旧判定直接套到原来的 C1 等 ID。QC 输出 `needs_review`，2 条满足本轮交付条件。其余因部分支持、无法精确定位等原因保留待复核；这不是“只有两条事实正确”的准确率结论。

## 验证与下一步

仅新增 4 项核心测试，覆盖正式报告与草稿隔离、重复渲染 / 证据变化、核验完整性、无效引用及 20 条预算以外的漏检；并强化既有 API 测试，检查执行完成但质量 blocked 的状态能一致保存和返回。

验证结果：71 项单元测试、2 项 API 集成测试通过；真实产物的离线回放及摘要检查通过。原始报告保持不变，本轮无真实 LLM 调用。

下一步需要人工确认的小样本金标准，再评估误报和漏报。数值 / 单位 / 实验条件的语义核对、自由文本到主张的语义绑定、完整章节覆盖和医学专项评估仍未完成。当前精确对应策略较保守，会将语义正确但改写过的内容留作待复核。
